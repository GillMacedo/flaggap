# Architecture

flaggap is one Go program in `plugin/scripts`, plus a skill that tells Claude when and how to run it.

## Flow

1. **Load manifests** (`load`, `parseFile`, `containers` in `manifest.go`). This happens first, so a bad file is refused before any build. Each argument is a file, a directory or `-`. A file is refused when it is empty, has no final line break, contains NUL bytes or `{{`, ends on a key with no value, or holds a document that isn't a Kubernetes object. Directories are walked for `.yaml`, `.yml` and `.json`, and refused when they hold a `Chart.yaml` or a kustomization. A file whose last object ends inside a container is refused unless it ends with a `---` or `...` line. `pick` selects the containers named with `--container`, or the only container.
2. **Build** (`buildProgram` in `program.go`). `go list -deps -json` finds the main package and refuses a package that isn't `main`, a module that imports a parser flaggap doesn't model, and a module that imports none of `flag`, `pflag` and `cobra`. `patchParse` renames `(*FlagSet).Parse` (and `ParseAll` where it exists) and puts a call to `flaggapHook` in front; the hook is a new file in the same package. The standard `flag` package and a vendored pflag are changed with `go build -overlay`. Go refuses overlays inside the module cache, so for pflag from the module cache `copyPflag` copies the module to the temporary directory, patches the copy, and builds with `-modfile` pointing at a copy of `go.mod` with a `replace`, or with `GOWORK` pointing at a copy of `go.work` with a `replace` (`workspaceReplace`).
3. **Run** (`binary.run`). The program runs with the container's arguments in an empty temporary directory with only `PATH`, `HOME`, `TMPDIR` and `FLAGGAP_DUMP` set, and is killed after `--timeout`. The hook acts on the first `Parse` call that reads the command line: a call from cobra's `ParseFlags`, any call when the program has no arguments, or a call whose arguments are a non-empty subsequence of `os.Args`. It writes every flag (name, shorthand, kind, whether it takes a value, default, deprecation message), pflag's normalized names and interspersed setting, then unsets `FLAGGAP_DUMP` so a nested `Parse` (pflag parses added Go flag sets) stays quiet, runs the real parser with `ContinueOnError` and output discarded, writes its error and leftover arguments, and exits. A program that exits, crashes or hangs before that is refused with its output, except cobra's "unknown command", which is reported.
4. **Replay** (`checkStd`, `checkPflag` in `argv.go`). The arguments are walked with the rules of the parser the hook reported. Findings that stop the parse call `fail` with the text the real error must contain. Arguments whose value comes from a variable flaggap can't see are given to the real parser with a placeholder value of the flag's kind, or dropped for custom kinds, and get a note.
5. **Confirm** (`checkArgs` in `flaggap.go`). The program runs again with the replay's arguments. A predicted failure must match the real error; then its arguments are removed and the program runs again, up to 30 times. A real error the replay didn't predict becomes `bad-value` when it names a flag, or `parse-error` with the error quoted. A predicted failure the real parser accepts is refused with exit 2. `ignored-after-positional` is checked against the real parser's leftover arguments, and a first parse that got only part of the arguments (outside cobra) is refused. Leftover positional arguments of a cobra command get a note, because cobra's `Args` check runs after flaggap stops.
6. **Report** (`printText`, JSON). Findings are sorted by severity. The summary line says how many containers were checked.

## Why run the program

Reading flag definitions from source can't tell which flag set the program parses. Libraries register flags on sets the program never parses (klog registers all its flags in an `init` on a private set, and the Kubernetes component base copies two of them), names are built at run time (`fmt.Sprintf("audit-%s-mode", plugin)`), and cobra merges persistent flags per command. An early static version listed 62 flags metrics-server doesn't accept and missed 23 it does, so it would have passed `--logtostderr`, which the real binary rejects. The hook reads the set at the moment of parsing, so it is exact for the arguments given.

## Exit codes

0 when nothing reaches `--fail-on`, 1 when something does, 2 when the input can't be trusted or the flags are wrong. Exit 2 prints only to stderr.
